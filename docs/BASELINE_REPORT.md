# 同源事件聚类基线实验报告

> 角色 C（系统工程）· 聚类模块
> 日期：2026-07-28

## 1. 实验目标

验证同源事件聚类技术路线的可行性：BGE embedding → FAISS 检索 → 相似度图聚类

## 2. 数据集结构

| Sheet | 内容 | 规模 | 字段 |
|-------|------|------|------|
| Sheet1 | 公司事件原文（含标签） | 1,525 条 | event_name, event_emotion, event_impact_analysis, duplication_id 等 |
| Sheet2 | 行业事件原文（含标签） | 556 条 | 同上（行业维度） |
| Sheet3 | 公司重复/转载文章 | 999 条 | duplication_id → 指向 Sheet1 原文 |
| Sheet4 | 行业重复/转载文章 | 500 条 | 同上 |

**关键发现**：真正的"同源关系"体现在 Sheet3/Sheet4 的转载文章与 Sheet1/Sheet2 原文的映射（654 对公司级），而非 Sheet1 内部。

## 3. 技术路线验证

### 3.1 BGE Embedding
- 模型：`BAAI/bge-large-zh-v1.5`（1024 维，CPU 推理）
- 文本：新闻正文（清洗后）
- 每篇约 45-55s/batch(64篇)，全量 2,524 篇约 30 分钟

### 3.2 FAISS 检索召回

**场景**：654 篇转载文章 → 在 1,525 篇原文库中检索

| 指标 | 结果 |
|------|------|
| **Recall@1** | **97.7%** (639/654) |
| **Recall@3** | **99.2%** |
| **Recall@5** | **99.5%** |
| **Recall@10** | **99.7%** |

**结论**：BGE + FAISS 召回能力极强，同源文章几乎总能命中 Top-10。

### 3.3 相似度分布分析

| 类型 | 相似度 |
|------|--------|
| 同源对（转载↔原文） | median = 0.9986, min = 0.4755 |
| 非同源对（随机配对） | median = 0.5465, max = 0.8596 |

- **转载去重**：阈值 0.80 即可达到 F1 = 0.9962
- **事件聚类**：需更高阈值（0.94+）保证精确

### 3.4 聚类策略对比

> 口径说明：本节的 HDBSCAN 网格调参在 **Sheet1 原文（1,525 篇）** 上进行，ground truth 仅含原文内部共享 duplication_id 的组（207 组 / 513 篇），未包含转载对。

| 策略 | purity | ARI |
|------|--------|-----|
| HDBSCAN（网格调参最优） | 0.577 | 0.076 |
| **相似度图 + 连通分量（阈值0.96）** | **0.967** | **0.967** |

**结论**：在仅原文口径下，相似度图 + 连通分量显著优于 HDBSCAN。

### 3.7 同口径复核（原文 + 转载，2,524 篇）

将 Sheet1 原文 + Sheet3 转载合并、用综合 ground truth（原文↔转载 + 原文间共享 ID，422 组 / 1,082 篇）同口径对比：

| 策略 | purity | ARI | NMI | 组检测率 | 簇数 |
|------|--------|-----|-----|----------|------|
| **相似度图 + 连通分量（阈值0.94）** | 0.964 | 0.791 | 0.989 | **97.6%** | **532** |
| HDBSCAN（网格最优 2,1,0.0） | 0.992 | 0.903 | 0.992 | 95.3% | 728 |

**解读**：
- HDBSCAN 的 purity/ARI 略高，因其 ground truth 以「转载↔原文」近复制对为主，HDBSCAN 对密度连接天然敏感；
- 但 HDBSCAN 产生 **728 簇**（gt 仅 422 组）——严重过分割，把同一事件的多篇报道拆碎，组检测率反而落后（95.3% vs 97.6%）。

**生产决策**：默认相似度图 + 连通分量（阈值 0.94），理由：
1. 组检测率更高、不过分割（532 vs 728 簇），更符合"事件跟踪"（一个事件 = 一条时间线）的目标
2. 阈值语义可解释（= 语义相似度门槛），调参直观
3. 天然支持**增量归组**：新文章 → FAISS 检索 → 匹配阈值即归入既有事件组（流式场景）
4. HDBSCAN 保留为离线批处理备选（`config.yaml` 中 `method` 可切换 graph/hdbscan/dbscan）

### 3.8 行业数据验证（Sheet2 + Sheet4，1,056 篇）

将行业原文 + 转载合并、用行业版 ground truth（212 组 / 583 篇）重复端到端评估，验证技术路线能否泛化：

| 阈值 | purity | ARI | NMI | 组检测率 |
|------|--------|-----|-----|----------|
| 0.90 | 0.9348 | 0.8524 | 0.9847 | 98.11% |
| **0.92** | **0.9451** | **0.8530** | **0.9861** | **97.17%** |
| 0.94 | 0.9468 | 0.7996 | 0.9834 | 96.23% |

**结论**：图聚类在行业维度同样有效（最佳 ARI=0.853 @ 阈值0.92，组检测率 97%），
验证了"BGE + FAISS 相似度图 + 连通分量"路线的**通用性**。公司维度最优阈值 0.94 在行业上仍可用（purity=0.947），
行业最佳 ARI 阈值略低（0.92），生产上建议按维度分别配置阈值（`config.yaml` 的 `similarity_threshold`）。

## 3.6 端到端全量评估（Sheet1 + Sheet3 合并，2,524 篇）

ground truth：422 组，覆盖 1,082 篇文章（原文 + 指向它的转载同组）

| 阈值 | purity | ARI | NMI | 组检测率 |

## 4. 生产级 Pipeline 设计

```
新文章 → 清洗 → BGE向量化 → FAISS检索Top-K
                              ↓
                    相似度 ≥ 阈值？
                    /          \
               是（归入事件组）  否（新建事件组）
```

- **去重（转载检测）**：低阈值 0.80-0.85，高召回
- **事件聚类**：高阈值 0.94-0.96，高精确
- **双阈值策略**：先低阈值召回候选，再高阈值确认组归属
