## 5. 事件识别 + 要素抽取（任务②③④）

### 5.1 对带标签测试集（同时自动出评测报告）
```bash
python -m event_ner.run --source tagged_test
```

### 5.2 对无标签数据批量抽取（产结构化 JSONL）

**小批量验证**（建议先跑，确认输出格式）：
```bash
python -m event_ner.run --source unlabeled_test --limit 1000 --workers 8
```

**全量抽取**（混合策略 + 断点续跑 + 并行）：
```bash
python -m event_ner.run --source unlabeled_test --workers 8
```

参数说明：
- `--source`：`tagged_test` / `tagged_train` / `unlabeled_test` / `unlabeled_train`
- `--limit`：只处理前 N 条（不传则全部）
- `--workers`：并行线程数（默认 4；网络 IO 密集，可开 8）
- `--rule-only`：纯规则抽取（跳过 LLM，快/免费，准确率约 67%）
- `--redo-rule`：丢弃已有规则兜底结果，重新走 LLM（API 恢复后补抽用）

**输出与断点**：
- 结果：`outputs_event/extracted_{source}.jsonl`（每行一个 JSON，边跑边写）
- 断点：`outputs_event/.{source}.ckpt.json`（中断后重跑同一条命令自动续跑，不重复）
- 进度监控：`python monitor.py`（Windows 友好，无需 tail/grep）

> 抽取结果每条 JSON 字段见《接口对接文档.md》第 4 节。相比之前新增了 `source_type`（新闻/公告/研报/政策文件）字段，其余字段与 HTTP 接口完全一致。

## 9. 常见问题

**Q1：LLM 调用失败 / 超时？**
检查 `config.json` 的 `api_key` 是否正确、网络能否访问 `api.deepseek.com`。失败时会自动回退规则模式（不会报错中断），可看日志 `[LLM] 调用失败: ...`。

**Q2：提示"未找到事件体系文件"？**
说明数据目录不在预期位置。确认 `../data/事件类型_标的.json` 存在；若数据在别处，改 `event_ner/paths.py` 里的候选路径。

**Q3：想换 Qwen 或 GLM？**
改 `config.json` 的 `provider` 和 `base_url`：
- Qwen：`provider=qwen`，`base_url=https://dashscope.aliyuncs.com/compatible-mode/v1`，`model=qwen-plus`
- GLM：`provider=glm`，`base_url=https://open.bigmodel.cn/api/paas/v4`，`model=glm-4-flash`

**Q4：要做 LoRA 微调？**
`outputs_event/llm_sft.jsonl` 已是标准 Chat 格式，可用 `transformers + peft` 直接加载微调（依赖见 requirements.txt 注释部分）。

**Q5：API 密钥安全？**
`config.json` 已加入 `.gitignore`，**不要提交到代码仓库或发给他人**。

**Q6：DeepSeek 返回 402（余额不足）？**
批量抽取会自动回退规则模式继续跑（不会中断），但结果质量下降。充值后执行 `--redo-rule` 即可把规则兜底部分重新用 LLM 补抽。

**Q7：无标签输出为什么是 .jsonl 而不是 .json？**
大规模批量抽取采用 JSONL（每行一个 JSON）便于增量写盘、断点续跑和下游流式消费。带标签评测仍是 `.json`。
